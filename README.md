# توصيل — الموقع الإلكتروني

موقع عربي كامل (RTL) لمنصة توصيل، يشمل الموقع العام، بوابة العميل، بوابة
موظفي الفروع، لوحة إدارة، تتبع الشحنات، تسجيل دخول العملاء عبر رمز SMS، وقاعدة بيانات
SQLite دائمة.

> **ملاحظة:** هذه النسخة جاهزة للتشغيل والمراجعة، ولم يتم نشرها على الإنترنت بعد. بيانات
> التواصل الحالية تجريبية ويجب استبدالها من لوحة الإدارة قبل الإطلاق.

## ما الذي تم بناؤه

- **الموقع العام:** الرئيسية، الخدمات، من نحن، الأسئلة الشائعة، تتبع الشحنة، اتصل بنا،
  سياسة الخصوصية، والشروط والأحكام.
- **تتبع الشحنات:** صفحة عامة + واجهة JSON على `/api/track/<code>`.
- **بوابة العميل:** لوحة إحصائية، الشحنات، تفاصيل الشحنة، الملف الشخصي، والإشعارات.
- **بوابة موظفي الفروع:** دخول داخلي مستقل، لوحة شحنات الفرع، تحديث الحالة وإضافة حدث
  تتبع، والملف الشخصي. لا يرى الموظف إلا الشحنات المسندة إلى فرعه.
- **لوحة الإدارة:** إدارة الشحنات وأحداث التتبع، العملاء، الفروع، موظفي الفروع، طلبات
  التواصل، الإعدادات، كلمة المرور، وسجل النشاط. وتتضمن صفحة **بيانات التجربة**
  `/admin/demo` لدليل الموظفين وحسابات العرض التجريبي والشحنات وخطوات الفحص.
- **المصادقة:** دخول العملاء برمز تحقق عبر SMS بدون كلمة مرور، ودخول الإدارة وموظفي
  الفروع بالبريد وكلمة المرور، مع جلسات منفصلة لكل نوع حساب.
- **التخزين:** SQLite مع WAL، جلسات مخزنة في قاعدة البيانات، حماية CSRF، وحدود معدل للطلبات.
- **الإشعارات:** إشعارات داخل البوابة عند تحديث الشحنة، مع إمكانية إرسال SMS اختياري.
- **جاهزية النشر:** `requirements.txt`، `.env.example`، `Dockerfile`، `Procfile`،
  `render.yaml`، ودليل نشر تفصيلي في [DEPLOYMENT.md](DEPLOYMENT.md).

## التشغيل المحلي

### المتطلبات

- Python 3.12 أو أحدث
- Windows أو Linux/macOS

### الخطوات

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\run.ps1 -Open
```

أو على Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python server.py --open
```

يعمل الموقع محلياً على `http://127.0.0.1:8080/`.

### بيانات التطوير

- **لوحة الإدارة:** `http://127.0.0.1:8080/admin/login`
  - البريد: `admin@tawseel.local`
  - كلمة المرور: `Admin1234!`
- **بوابة موظفي الفروع:** `http://127.0.0.1:8080/staff/login`
  - البريد: `staff@tawseel.local`
  - كلمة المرور: `Staff1234!`
  - الفرع التجريبي: `MCT` — فرع مسقط
- **عميل تجريبي:** `+96891234567`
- **رموز شحنات تجريبية:** `TS1392042`، `TS2026001`، `TS2026002`، `TS2026003`،
  `TS2026004`، `TS2026005` (كلها مسندة إلى فرع مسقط التجريبي)

في وضع التطوير يظهر رمز OTP أسفل صفحة التحقق، وتُطبع رسائل SMS في سجل الخادم. هذا السلوك
ممنوع تلقائياً عند `APP_ENV=production`.

> غيّر كلمة مرور المدير قبل الإطلاق من `/admin/password`، وغيّر كلمة مرور حساب
> الموظف التجريبي أو أوقفه من `/admin/staff` قبل الإنتاج.

ينشئ `SEED_DEMO=1` في التطوير فرع مسقط وحساب الموظف التجريبي تلقائياً، ويسند الشحنات
التجريبية غير المرتبطة إلى الفرع. لا يتم إنشاء هذه البيانات في الإنتاج. يمكن لفريق
العمل فتح صفحة **بيانات التجربة** من `/admin/demo` بعد تسجيل دخول الإدارة؛ تجمع
الحسابات التجريبية والشحنات وخطوات الفحص، مع إخفاء كلمات المرور تلقائياً في الإنتاج.

إدارة الفروع من `/admin/branches` وإدارة الحسابات من `/admin/staff`. لا يوجد تسجيل
عام لموظفي الفروع؛ ينشئ مدير النظام الحساب ويحدد الفرع والدور.

## الإعدادات

انسخ `.env.example` إلى `.env` للتطوير المحلي، أو أضف المتغيرات في منصة الاستضافة.
أهم المتغيرات:

| المتغير | الوصف |
|---|---|
| `APP_ENV` | `development` أو `production` |
| `SECRET_KEY` | مفتاح سري طويل؛ إلزامي في الإنتاج |
| `PUBLIC_BASE_URL` | الرابط العام النهائي، مثال `https://tawseel.example.com` |
| `DATA_DIR` | مجلد قاعدة البيانات والملفات السرية |
| `SHIPMENT_CODE_PREFIX` | بادئة أكواد الشحنات المولّدة تلقائياً (افتراضياً `TS`) |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | تُستخدم لإنشاء أول حساب إدارة فقط |
| `SMS_PROVIDER` | `log` للتطوير، أو `twilio` / `unifonic` |
| `TWILIO_*` / `UNIFONIC_*` | بيانات مزوّد الرسائل |
| `TRUST_PROXY` | `1` عند التشغيل خلف Nginx/Caddy/Render |
| `SESSION_COOKIE_SECURE` | `1` عند استخدام HTTPS |
| `DEV_SHOW_OTP` | إظهار رمز OTP في التطوير فقط |
| `SEED_DEMO` | إدخال بيانات تجريبية في التطوير فقط |

يمكن أيضاً تعديل اسم الشركة والهاتف والبريد والعنوان وساعات العمل وروابط التواصل من
`/admin/settings` بعد تسجيل الدخول.

## الأمان

- كلمات مرور الإدارة والموظفين تُخزّن باستخدام `scrypt`، ولا تُخزّن رموز OTP نصاً صريحاً في الإنتاج.
- جلسات المصادقة مخزنة في قاعدة البيانات ومرتبطة بكوكي `HttpOnly` / `SameSite=Lax`.
- بوابة الموظفين تستخدم كوكي `tawseel_staff` وجلسة منفصلة (12 ساعة)؛ جلسة الموظف لا تمنح
  وصولاً إلى لوحة الإدارة أو بوابة العميل. يُنهى وصول الموظف فوراً عند إيقاف الحساب أو
  الفرع أو تغيير كلمة المرور أو الفرع.
- كل استعلامات بوابة الفرع مقيّدة بـ `branch_id` الخاص بالموظف، مع اختبارات للوصول
  العرضي إلى شحنات فرع آخر.
- حماية CSRF لكل النماذج، وحدود معدل للتواصل، OTP، دخول الإدارة، دخول الموظفين، وتتبع API.
- رؤوس أمان: CSP مع nonce، `X-Frame-Options`، `nosniff`، و`Referrer-Policy`.
- في الإنتاج: `SECRET_KEY` إلزامي، وOTP التطوير والبيانات التجريبية معطّلة قسرياً.

## الرسائل النصية

- **Twilio:** اضبط `TWILIO_ACCOUNT_SID` و`TWILIO_AUTH_TOKEN` و`TWILIO_FROM` (رقم E.164).
- **Unifonic:** اضبط `UNIFONIC_APPSID` و`UNIFONIC_SENDER`، ويمكن تعديل `UNIFONIC_URL`.
- **التطوير:** `SMS_PROVIDER=log` يطبع الرمز في السجل ويعرضه في صفحة التحقق.

لا يمكن تسليم OTP الحقيقي قبل إضافة بيانات مزوّد معتمد. تحقق من `/health` لمعرفة حالة
قاعدة البيانات والرسائل.

## ملاحظات

- SQLite مناسب لنسخة واحدة من التطبيق. عند التوسع لعدة نسخ أو حمل كتابة كبير، انتقل إلى
  PostgreSQL.
